# 스펙트럼 차트에서 특정 bin이 단독으로 튀는 현상

**증상**: 500Hz+10kHz 혼합 음원(약 3초, Fc=2000Hz)을 필터링한 뒤 스펙트럼 차트를 보면, 필터링 후(빨간색) 곡선이 10kHz 근처 x좌표에서 "딱 한 개의 점"만 그래프 최상단(+20dB 클램프)까지 치솟았다가 바로 다음 점에서 원래 수준(-80dB 근처)으로 돌아온다. 실시간 앱 화면(일반 해상도 스크린샷)에서는 눈에 띄지 않지만, SVG `d` 속성을 직접 읽어보면 `L459.53,132.00 L459.53,0.03 L459.54,132.00`처럼 단일 좌표에서만 값이 튄다.

**근거**: 브라우저 콘솔에서 `document.querySelector('svg[aria-label*="스펙트럼"]')`의 `filtered` path `d` 속성을 정규식으로 파싱해 직접 확인함. 반면 동일한 설정으로 저장된 WAV 파일을 다시 디코딩해 순수 JS로 FFT를 재현하면 해당 주파수 근방에서 이런 튀는 값이 재현되지 않음(최대값이 주변 bin과 비슷한 수준).

**의심되는 원인**: `encodeWavFile`이 `Math.max(-1, Math.min(1, value))`로 오디오 샘플을 클램프하기 때문에, WAV로 저장된 뒤 다시 읽은 신호에는 이상치가 가려졌을 가능성이 있다. 즉 `filtered[0]`(인코딩 전 원본 float 배열) 자체에 극단적으로 큰 값(또는 Infinity에 가까운 값)이 포함된 특정 샘플이 있고, 이게 스펙트럼 계산에는 그대로 반영되지만 WAV 인코딩 시에는 클램프되어 사라지는 것으로 보인다.

**시도한 것**: 저장된 WAV를 재디코딩해 FFT를 재현(이상치 재현 안 됨). 실제 앱 화면의 저해상도 스크린샷으로는 육안 확인 어려움.

**제안하는 다음 단계**: `applyBiquadCascade` 또는 `designButterworthLowpass`가 특정 입력 조건(긴 음원, 특정 Fc/Order 조합)에서 극단적인 값을 한 샘플만 생성하는지 격리된 단위 테스트로 확인한다. 특히 롱런 상태에서 부동소수점 상태(`lpf_state`에 해당하는 z1/z2)가 비정상적으로 커지는 순간이 있는지 `filtered[0]`의 최대 절댓값을 직접 로깅해 확인하는 게 빠른 다음 단계다.
