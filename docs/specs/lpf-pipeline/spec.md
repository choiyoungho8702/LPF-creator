# LPF Pipeline: 시뮬레이션 + 실시간 C 코드 생성

## User-visible outcomes

사용자는 음원 파일(또는 원시 데이터)을 불러온다. 기본 흐름은 **스마트 추천으로 기본 설정값을 먼저 받고, 제어 패널에서 그 값을 미세 튜닝하는 것**이다(추천을 쓰지 않고 처음부터 직접 설정하는 것도 가능하다). 설정이 끝나면 한 번의 실행으로 다음 세 가지를 함께 얻는다: 필터링된 결과 음원(WAV), 시각적·수치적 검증 결과(스펙트럼, 오버플로우, 양자화 오차), 그리고 실제 프로젝트에 바로 통합 가능한 실시간 C 코드. 결과가 마음에 들지 않으면 제어 패널에서 파라미터를 다시 조정해 재실행할 수 있다.

## Approved scope

- 오디오 입력: 표준 포맷(.wav/.flac) 자동 헤더 파싱 + 원시 데이터(.raw/.pcm) 수동 스펙 입력
- 스마트 자동 추천 (FFT 기반 Fc/Order 제안 — 제어 패널에 기본값으로 채워짐)
- 제어 패널: Fs, Fc, Order, Q-Format, Channel Mode, 연산 방식(정수 고정소수점/부동소수점), 블록 크기 — 추천값을 받은 뒤 미세 튜닝하거나, 처음부터 직접 설정 가능. 필터 설계 방식은 Butterworth만 제공한다.
- 프리셋 저장/불러오기 (JSON)
- 시각적·기술적 검증: FFT 스펙트럼 오버레이, 정수 오버플로우 감지, 양자화 오차 비교
- 결과물 출력: 필터링된 WAV 음원, 실시간 C 코드(화면 표시 + 원클릭 복사)

## Observable acceptance criteria

1. `.wav`/`.flac` 업로드 시 Fs, 비트 뎁스, 채널 수가 자동으로 제어 패널에 채워진다.
2. `.raw`/`.pcm` 업로드 시 Fs/비트 뎁스/채널 수를 직접 입력하는 팝업이 뜨고, 값을 입력해야 다음 단계로 진행할 수 있다.
3. "스마트 추천"을 실행하면, 로드된 음원의 FFT 분석을 바탕으로 Fc/Order 등 추천값이 제어 패널에 기본값으로 채워진다. 이 단계는 선택 사항이며, 사용자는 추천을 거치지 않고 처음부터 직접 값을 설정할 수도 있다.
4. 제어 패널에서 Fs, Order(2/4/6/8), Q-Format(Q15/Q23/Q31), Channel Mode(Mono/Stereo L-R Interleaved), 연산 방식(정수/부동소수점), 블록 크기를 각각 선택·조정할 수 있다 — 추천값을 그대로 쓰거나 미세 튜닝하거나, 직접 처음부터 설정하는 것 모두 가능하다. 필터 설계 방식은 Butterworth로 고정이다.
5. Fc는 자유롭게 입력할 수 있지만, Fc ≥ Fs/2(Nyquist)로 설정한 상태에서는 실행이 차단되고 명확한 에러 메시지가 표시된다(자동 보정 없음, 경고가 아니라 차단).
6. 현재 제어 패널 설정 전체를 JSON으로 내보내거나, JSON 파일을 불러와 복원할 수 있다.
7. 유효한 설정에서 실행하면 다음이 함께 생성된다:
   - 원본과 필터링 후 스펙트럼을 겹쳐 보여주는 FFT 그래프
   - 정수 연산 모드에서, 지정한 비트 범위를 초과하는 구간이 있으면 빨간 경고가 표시된다(실행 자체는 차단하지 않음)
   - 이상적 부동소수점 결과와 실제 정수 연산 결과 간 양자화 오차 비교
   - 필터링된 결과를 WAV로 청음할 수 있다(입력 포맷과 무관하게 출력은 항상 WAV)
   - 선택한 연산 방식·블록 크기를 반영한 실시간 처리용 순수 C 코드가 화면에 텍스트로 표시되고 원클릭 복사가 가능하다
8. 실행 처리 중에는 진행 상태(로딩 표시)가 사용자에게 보인다.
9. 생성된 C 코드는 특정 MCU/컴파일러에 종속되지 않는 플랫폼 독립적 C이며, 정수 모드에서는 비트 시프트 연산과 포화(saturation) 처리를 포함한다.

## Settled constraints and rationale

- 필터 종류는 LPF만 다룬다. HPF/BPF/노치 등은 범위 밖 — `PRODUCT.md`의 경계를 그대로 따르며, 확장 여부는 의도적으로 보류된 상태다.
- 실행은 통합형이다: 음원 생성·검증·C 코드 생성이 하나의 실행으로 함께 일어난다. 코드 생성에 필요한 입력이 시뮬레이션 설정과 동일하고 계수 계산 자체가 가벼워, 분리해서 얻는 이득보다 단계를 줄이는 이득이 크다고 판단했다(사용자 확인).
- 블록 크기와 연산 방식(정수/부동소수점)은 고정값이 아니라 선택 파라미터다. 특정 하드웨어나 설계를 전제하지 않는다는 원칙과 일관된다(사용자 확인).
- 필터 설계 방식은 Butterworth만 제공한다. 실무에서 가장 무난하고 널리 쓰이는 선택이라는 이유로, Chebyshev I/Elliptic 등 다른 설계 방식은 범위에서 제외했다(사용자 확인).
- Fc는 자동으로 제한하지 않되, Fs/2(Nyquist) 이상이면 실행을 차단한다. 오버플로우처럼 "실행은 되지만 품질이 나쁠 수 있다"는 경고가 아니라, 그 이상에서는 필터 설계 수식 자체가 수학적으로 정의되지 않아 의미 있는 결과가 나오지 않기 때문이다(사용자 확인).
- 출력 음원은 입력 포맷과 무관하게 항상 WAV다. mp3/flac처럼 손실 포맷으로 재인코딩하면 LPF 자체의 효과가 아니라 추가 압축 아티팩트가 청음 검증에 섞이기 때문이다(사용자 확인). 비트 뎁스는 입력과 동일하게(16/24비트) 유지한다.
- 스마트 자동 추천 기능은 이번 스펙 범위에 포함한다. `PRODUCT.md`에서는 의도적으로 결정을 보류해 두었던 항목이며, 이번 작업 단위에서 포함하기로 확정했다(사용자 확인).

## Assumptions

- Assumption: 실행 처리 중에는 로딩/진행 상태를 사용자에게 보여준다. 음원 길이가 가변적이라 체감 지연이 달라질 수 있으므로, 길이에 따른 성능은 구현 후 확인이 필요하다(아래 리스크 참고).
- Assumption: 채널은 Mono / Stereo(L-R Interleaved)까지만 지원한다. 5.1 등 멀티채널은 다루지 않는다.
- Assumption: Q-Format은 Q15=16비트, Q23/Q31=32비트 컨테이너로 해석한다(임베디드 DSP 관례).
- Assumption: 스마트 추천은 Hann 윈도우를 적용한 FFT로 원본 스펙트럼을 분석해, 피크 대비 -60dB 아래로 떨어지는 지점 이후를 "에너지가 사실상 사라진" 구간으로 보고 그 바로 아래 유효 주파수를 Fc로 추천한다(구현 완료, `lib/smart-recommend.ts`). Order는 현재 추천하지 않고 사용자가 직접 선택한다. 추천값은 제어 패널에 자동으로 채워지며 사용자가 자유롭게 수정할 수 있다.
- Assumption: Order 선택지는 2/4/6/8로 제한한다(2차 biquad 섹션을 단위로 한 cascade 구조와 일치).

## Off-limits areas and why

- mp3 입력 지원: mp3는 손실 압축 포맷이라 헤더에 비트 뎁스 정보가 없어, wav/flac과 동일하게 세 값(Fs/비트 뎁스/채널 수)을 자동으로 채우는 모델이 성립하지 않는다. 표준 포맷 자동 파싱은 wav/flac만 다루기로 범위를 좁혔다(사용자 확인).
- LPF 외 다른 필터 타입(HPF/BPF/노치 등): `PRODUCT.md`에서 의도적으로 보류된 경계이며 이번 작업 단위에서 다루지 않는다.
- Chebyshev I, Elliptic 등 Butterworth 외 필터 설계 방식: 실무에서 Butterworth가 가장 널리 쓰인다는 이유로 이번 작업 단위에서는 제외했다(사용자 확인). 필요하면 추후 재검토한다.
- 멀티채널(5.1 등) 지원: 현재 가정상 범위 밖이다.
- 특정 MCU/컴파일러 타겟 최적화: `PRODUCT.md` 경계상 플랫폼 독립적 순수 C만 다룬다.

## Deferred points

None identified. `PRODUCT.md`에서 보류되어 있던 항목(스마트 추천 포함 여부)은 이번 스펙에서 범위에 포함하기로 결정했고, 필터 설계 방식 선택 가능 여부는 Butterworth만 제공하는 것으로 결정했다.

## Remaining risks

- 음원 길이가 길면 통합 실행 방식의 체감 처리 시간이 길어질 수 있다. 필요 시 비동기 처리나 실행 분리로 재검토할 수 있다.
- flac 실제 오디오 디코딩(헤더 외 압축 프레임)은 구현되지 않았다 — `docs/follow-ups/flac-audio-decoding.md`에 기록.
- 생성된 C 코드는 실제 C 컴파일러로 컴파일 검증되지 않았다(이 개발 환경에 컴파일러가 없음) — `docs/follow-ups/c-code-compile-verification.md`에 기록.
- 스마트 추천의 -60dB 임계값은 합리적인 기본값으로 선택했을 뿐, 실제 다양한 음원에서 추천 품질이 만족스러운지는 사용해보며 검증이 필요하다.
